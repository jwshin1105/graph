# 수학 탐구용 계산기

식을 계산해 주는 프로그램이 아니라, **수학적 대상을 정확하게 계산하고, 시각화하고,
그 안의 구조와 규칙성을 탐색하는** 파이썬 데스크톱 앱입니다.

## 설치

파이썬을 따로 깔 필요 없습니다. 필요한 것은 모두 안에 들어 있습니다.

| 운영체제 | 받을 것 | 여는 법 |
| --- | --- | --- |
| 윈도우 | `수학탐구계산기-1.0.0-설치.exe` | 두 번 눌러 설치. 관리자 권한이 필요 없습니다. |
| 윈도우 (설치 없이) | `…-windows-x64-portable.zip` | 풀어서 `graphcalc.exe` |
| 맥 | `수학탐구계산기-1.0.0.dmg` | 앱을 Applications 로 끌어다 놓기 |
| 데비안·우분투 | `graphcalc_1.0.0_amd64.deb` | `sudo apt install ./graphcalc_1.0.0_amd64.deb` |
| 그 밖의 리눅스 | `…-linux-x86_64.tar.gz` | 풀고 `./install.sh` (홈에 설치, 권한 불필요) |

설치본은 [Actions](../../actions/workflows/build.yml) 의 최근 실행에 붙어 있고,
판이 매겨진 것은 [Releases](../../releases) 에 있습니다.

맥에서 처음 열 때 "확인되지 않은 개발자" 라고 나오면 앱을 오른쪽 클릭 → **열기**
를 고르세요. 애플 개발자 인증서로 서명하지 않았기 때문이고, 한 번만 그렇게 하면 됩니다.

```bash
pip install -r requirements.txt

```

아이콘을 만들고, 하나로 묶고, **묶은 것을 실제로 띄워 본 다음**, 그 운영체제의

## 0. 이 프로그램이 지키는 것

### 0-1. 정확도가 가장 앞선다

배정밀도(float64)로 재면 `0.1 + 0.2` 가 `0.30000000000000004` 가 되고,
`(√2)²` 가 `2.0000000000000004` 가 됩니다. 여기서는 그렇게 하지 않습니다.

| 입력 | 이 프로그램 | 배정밀도로 재면 |
| --- | --- | --- |
| `0.1 + 0.2` | `3/10` | 0.30000000000000004 |
| `sqrt(2)^2` | `2` | 2.0000000000000004 |
| `10^16 + 1 - 10^16` | `1` | 0 |
| `sin pi` | `0` | 1.2246×10⁻¹⁶ |
| `(1 + 1/10^6)^(10^6)` | `2.7182804693193768…` | 2.7182804690957534 |

계산의 순서는 늘 같습니다.

1. **정확히** — SymPy 로 기호 계산. 유리수는 유리수로, π 와 √2 는 π 와 √2 로 남습니다.
2. **고정밀로** — mpmath 로 원하는 자릿수까지. 자릿수를 두 번 달리 잡아 서로 견주어
   **실제 오차를 잽니다.** "아마 맞겠지" 로 넘기지 않습니다.
3. **못 구했으면 못 구했다고** — 틀린 숫자를 내놓는 것보다 낫습니다.

배정밀도는 **그림을 그릴 때만** 씁니다. 화면의 한 픽셀보다 훨씬 작은 오차라
눈에 보이지 않고, 대신 아주 빠르기 때문입니다. 계산 결과로는 쓰지 않습니다.

### 0-2. 계산하는 값과 보여 주는 값은 다르다

화면에 12자리로 줄여 적었다고 해서 그 값으로 다음 계산을 이어가면 안 됩니다.
그래서 **내부 자릿수**(계산용)와 **표시 자릿수**(화면용)를 따로 둡니다.
왼쪽 아래 「정밀도」에서 둘을 따로 조절할 수 있고, 표시 자릿수를 3 으로 낮춰도
내부 계산은 흔들리지 않습니다.

```
계산 자릿수  50      ← mpmath 가 쓰는 유효자릿수
표시 자릿수  12      ← 화면에 적는 유효자릿수
그래프 허용 오차 ε  0.08 픽셀
```

식으로도 바꿀 수 있습니다 — `precision = 100`, `digits = 40`, `epsilon = 0.01`.

수치로 구한 값은 **오차가 허락하는 자릿수까지만** 적습니다. 못 믿을 자릿수를
보여 주는 것은 거짓말이기 때문입니다.

### 0-3. 층이 나뉘어 있다

```
입력 → Parser → AST → 정의역 분석 → 해집합 표현 → 정확·고정밀 계산 → 구조 분석 → 렌더링
```

| 층 | 위치 | 하는 일 |
| --- | --- | --- |
| Parser·AST | `core/parser.py`, `core/syntax.py` | 사람이 적는 표기를 SymPy 식과 문장으로 |
| 정의역 | `core/domain.py` | ℤ·ℕ·ℚ·ℝ, 이산과 연속의 구분 |
| 해집합 | `core/solution.py` | 점·점열·곡선·영역·격자점을 수학적으로 표현 |
| 계산 | `core/evaluate.py`, `core/precision.py` | 정확값 우선, 고정밀 대비, 오차 관리 |
| 객체 | `objects/` | 한 줄이 무엇인지 가려내기, 수열·점열 엔진 |
| 그래프 | `engine/` | ε 기반 적응 샘플링 |
| 분석 | `analysis/` | 규칙성 탐색, 가설 검증 |
| 화면 | `ui/` | PySide6 데스크톱 앱 |

**렌더링은 정확도를 낮추지 못합니다.** 무엇을 그릴지는 해집합 표현이 이미 정해
두었고, 화면 층은 그것을 화면 크기와 허용 오차에 맞춰 옮길 뿐입니다.

## 1. 다룰 수 있는 대상

| 적는 법 | 유형 | 그리는 법 |
| --- | --- | --- |
| `y = x^2 - 3` | 함수 y = f(x) | 이어진 곡선 |
| `x = y^2` | 함수 x = g(y) | 이어진 곡선 |
| `x^2 + y^2 = 4` | 음함수 F(x, y) = 0 | 적응형 등고선 |
| `y > x^2 - 1` | 부등식 | 칠한 영역 + 테두리 |
| `C(t) = (cos t, sin t)` | 매개변수 곡선 | 이어진 곡선 |
| `r = 1 + cos theta` | 극좌표 곡선 | 이어진 곡선 |
| `(3, 4)` | 점 | 점 하나 |
| `[1, 4, 9, 16]` | 값의 목록 | 점들 |
| `[(0,0), (1,2), (2,5)]` | 점의 목록 | 점들 |
| `a_n = 2n - 1` | 수열 | 점 (n, aₙ) |
| `a_{n+1} = a_n + 3`, `a_1 = 1` | 점화식으로 정의된 수열 | 점 (n, aₙ) |
| `P(n) = (n, n^2), n ∈ Z` | **점열** | **점들 — 잇지 않음** |
| `x^2 + y^2 = 25, x ∈ Z, y ∈ Z` | 격자점 해 | 점들 |
| `0.1 + 0.2` | 값 | — |

정의역은 `∈` 으로 적습니다 — `n ∈ Z`, `x ∈ N`, `q ∈ Q`, `t ∈ R`.
범위는 조건으로 — `P(n) = (n, n^2), n ∈ Z, 1 <= n, n <= 20`.

### 1-1. 이산과 연속은 결코 섞이지 않는다

`P(n) = (n, sin n), n ∈ Z` 는 **점 열네 개**이지, 물결치는 곡선이 아닙니다.
이 구분은 렌더링이 짐작하는 것이 아니라 정의역 분석이 정하고, 해집합 표현이
들고 있습니다. 점을 선으로 잇고 싶으면 **직접 말해야** 합니다.

```
P(n) = (n, sin n), n ∈ Z              점으로만
P(n) = (n, sin n), n ∈ Z, connect     점 + 잇는 선
```

아무 말이 없으면 `n`, `k`, `m` 은 정수로, 그 밖의 이름은 실수로 봅니다.

## 2. 그래프 — 허용 오차 ε 로 세분 정도를 정한다

고른 간격으로 훑으면 완만한 곳에서는 쓸데없이 촘촘하고 급한 곳에서는 모자랍니다.
그래서 기준을 하나로 둡니다 — **선분으로 이었을 때 실제 곡선에서 몇 픽셀 떨어지는가.**
그 값이 ε 보다 크면 그 자리만 반으로 나눕니다. 끝나는 조건이 "몇 번 나눈다" 가
아니라 "ε 보다 잘 맞을 때까지" 인 것이 핵심입니다.

### 2-1. 음함수 — 적응형 마칭 스퀘어

칸마다 아홉 점(네 꼭짓점·네 변의 중점·가운데)을 봅니다. 가운데 값이 꼭짓점들의
평균과 얼마나 어긋나는지(bend) 재면 그 칸에서 F 가 얼마나 휘어 있는지 알 수 있고,
그 휨을 기울기 |∇F| 로 나누면 **선분이 실제 곡선에서 떨어지는 거리**가 길이 단위로
나옵니다. 그 거리가 ε 픽셀보다 크면 칸을 넷으로 쪼갭니다.

| 곡선 | 조각 수 | 길이 | 참값과의 오차 |
| --- | --- | --- | --- |
| `x² + y² = 1` | 1 | 6.282935 | 4×10⁻⁵ |
| `x² + y² = 0.0004` (반지름 0.02) | 1 | 0.125475 | 1.5×10⁻³ |
| `x²/4 + y² = 1` | 1 | 9.688088 | 3.7×10⁻⁵ |
| `\|x\| + \|y\| = 1` | 1 | 5.656854 | 2×10⁻¹⁶ |
| `y² = x³ − x` | 2 (실제로 두 갈래) | 10.03 | — |
| `xy = 1` | 2 (실제로 두 갈래) | 16.60 | — |

반지름 0.02 짜리 원은 처음 격자에서 칸 하나보다 작지만 놓치지 않습니다.
부호가 바뀌지 않아도 값이 0 에 가까운 칸은 더 쪼개 보기 때문입니다.

끝점을 이어 붙일 때는 **반올림이 아니라 거리로** 맞춥니다. 격자에 반올림해 맞추면
1e−9 밖에 안 떨어진 두 점이 격자 경계를 사이에 두고 갈라져, 이어져야 할 곡선이
끊기고 엉뚱한 점끼리 이어집니다.

### 2-2. 함수 — 끊긴 자리에서는 잇지 않는다

아무리 쪼개도 어긋남이 줄지 않는 구간은 **끊긴 자리**입니다.

| 함수 | 조각 수 | 비고 |
| --- | --- | --- |
| `sin x` | 1 | 717번 계산으로 상대오차 7×10⁻⁶ |
| `sin 50x` | 1 | 잘게 흔들려도 한 조각 |
| `1/x` | 2 | x = 0 에서 끊김 |
| `tan x` | 5 | π/2 마다 끊김 |
| `floor x` | 10 | 계단마다 끊김, 세로줄이 생기지 않음 |
| `sign x` | 2 | |

화면 밖으로 한참 나간 구간은 쪼개지 않습니다. 1/x 의 x = 0 근처를 스무 번
쪼개 봐야 그림은 그대로고 시간만 들기 때문입니다.

### 2-3. 넓이는 칸을 세지 않는다

"참인 칸의 개수 × 칸 넓이" 로 세면 경계에 걸린 칸에서 통째로 틀립니다.
줄마다 안쪽 토막을 찾고 **양 끝을 이분법으로 잡아** 길이를 더합니다.
줄 수를 반으로 줄인 값과 견주어 남은 오차도 함께 적습니다.

| 영역 | 구한 값 | 참값 | 오차 |
| --- | --- | --- | --- |
| `x² + y² ≤ 1` | 3.141780 | 3.141593 | 1.9×10⁻⁴ |
| `y ≥ x²` 이고 `y ≤ 1` | 1.333375 | 1.333333 | 4.2×10⁻⁵ |
| `\|x\| + \|y\| ≤ 1` | 1.999911 | 2 | 8.9×10⁻⁵ |

### 2-4. 점열은 보이는 것만 센다

화면에 n = 3‥40 만 들어온다면 400번째 항까지 굳이 계산하지 않습니다.
xₙ 이 단조로우면 이분법으로 범위를 바로 찾고, 그렇지 않으면 바깥으로 넓혀 갑니다.
좌표는 `cos(3)` 이라는 **식 그대로** 들고 있다가 그릴 때만 배정밀도로 낮춥니다.
규칙을 찾을 때는 정확한 쪽을 씁니다.

## 3. 규칙성 탐색

### 3-1. 사실과 가설을 가른다 (가장 중요한 약속)

유한한 항으로는 규칙이 하나로 정해지지 않습니다. 1, 4, 9, 16 다음에 25 가
와야 할 이유는 없습니다. 그러므로

- 주어진 항에서 **계산해서 확인한 것**은 **사실**로,
- 그 항들과 들어맞는 **규칙 후보**는 **가설**로 적습니다.

항을 두 몫으로 나눠 **앞의 몫으로 규칙을 세우고 뒤의 몫으로 확인합니다.**
확인에 쓴 항은 규칙을 만들 때 쓰지 않았으므로, 들어맞았다면 우연이 아니라는 쪽으로
조금 더 기운 증거가 됩니다. 그래도 증명은 아닙니다.

```
[사실] 항 14개를 보았습니다 (n = 1‥14)
[사실] 본 항까지는 계속 커집니다 (증가)
[가설 (여분 5항 모두 들어맞음)] 2차 다항식 — aₙ = n²
   어떻게 구했나 — 2차 차분이 2 로 일정합니다. 그래서 2차 다항식으로 보고
   앞의 9항을 지나는 다항식을 구했습니다.
```

"이 수열은 aₙ = n² 이다" 라고 잘라 말하지 않습니다.

### 3-2. 수열에서 찾는 것

증가·감소·일정·교대 / 1차·2차·…·6차 차분 / 이웃한 항의 비 / 주기 /
등차(공차) / 등비(공비) / k차 다항식 / 지수 성장 / 점화식 후보
(aₙ₊₁ = p·aₙ + q, aₙ₊₂ = p·aₙ₊₁ + q·aₙ 를 **정확히 풀어서**) /
일반항 후보(rsolve) / 극한 / 성장률.

```
피보나치
  [가설 (여분 12항 모두 들어맞음)] 일반항 — aₙ = √5(-(1 - √5)ⁿ + (1 + √5)ⁿ)/(5·2ⁿ)
  [가설 (여분 5항 모두 들어맞음)]  점화식 — aₙ₊₂ = aₙ + aₙ₊₁

aₙ = sin n
  [가설 (여분 5항 모두 들어맞음)]  점화식 — aₙ₊₂ = -aₙ + 2aₙ₊₁·cos(1)
```

### 3-3. 점열에서 찾는 것

xₙ·yₙ 각각의 규칙 / ΔPₙ · Δ²Pₙ / 걸음의 길이 / 기울기 / 돌아간 각 /
원점에서의 거리 / x축·y축·원점 대칭 / 평행이동 / 회전과 일차변환 /
공선성 / **모든 점이 함께 만족하는 관계식**.

```
P(n) = (cos n, sin n), n ∈ Z
  [사실] 걸음의 길이가 모두 √(2 - 2cos(1)) 로 같습니다
  [사실] 모든 점이 원점에서 같은 거리 1 에 있습니다 — 원 위의 점입니다
  [사실] 그 관계는 원의 식입니다
  [가설 (여분 5항 모두 들어맞음)] 모든 점이 x² + y² = 1 을 만족합니다
  [가설 (여분 5항 모두 들어맞음)] 회전 — Pₙ₊₁ = [[cos(1), -sin(1)], [sin(1), cos(1)]]·Pₙ
                                  — 1 라디안만큼 돌립니다
```

### 3-4. 관계식은 어떻게 찾는가

총차수 d 이하의 단항식을 늘어놓고 점마다 그 값을 한 줄로 적어 행렬을 만들면,
**가장 작은 특이값에 딸린 벡터**가 곧 "모든 점에서 0 이 되는 계수" 입니다.
여기에 세 가지를 더합니다.

1. **자릿수를 넉넉히.** x⁶ 은 x 보다 크기가 훨씬 커서 배정밀도로는 행렬이
   나빠집니다. 열마다 크기를 맞추고 mpmath 로 (30 + 8d)자리에서 계산합니다.
2. **되돌린 식을 정확히 다시 확인.** 계수를 유리수로 되돌린 뒤, 그 식이
   **정확한 좌표**에서 정말 0 인지 SymPy 로 확인합니다. 수치로 "거의 0" 인 것과
   정말 0 인 것은 다릅니다.
3. **점을 넉넉히 두고 차수를 낮은 쪽부터.** 점 스무 개를 오차 없이 지나는
   5차 곡선은 **언제나** 있습니다. 단항식 수만큼 점이 있으면 관계는 반드시
   찾아지는데, 그건 발견이 아니라 셈의 결과일 뿐입니다. 그래서 단항식이 k개면
   점을 k + max(3, k/2)개 이상 쓰고, 그만한 점이 없으면 그 차수는 아예 말하지
   않습니다. 낮은 차수부터 올라가므로 흔한 경우는 아홉 점으로 곧 끝납니다.

총차수 6 까지 봅니다.

| 점열 | 찾아낸 관계 | 차수 | 쓴 점 |
| --- | --- | --- | --- |
| `(cos n, sin n)` | `x² + y² = 1` | 2 | 9 |
| `(n, 2n+1)` | `y = 2x + 1` | 1 | 6 |
| `(2cos n, 3sin n)` | `9x² + 4y² = 36` | 2 | 9 |
| `(n, n³)` | `y = x³` | 3 | 15 |
| `(n², n³)` | `x³ − y² = 0` — 첨점을 가진 3차곡선 | 3 | 15 |
| `(cos n, cos 3n)` | `y = 4x³ − 3x` | 3 | 15 |
| `(n, n⁴)` | `y = x⁴` | 4 | 22 |
| `(cos n, sin 2n)` | `4x⁴ − 4x² + y² = 0` | 4 | 22 |
| `(n, n⁵)` | `y = x⁵` | 5 | 31 |
| `(n, n⁶)` | `y = x⁶` | 6 | 42 |
| `(n, √(n³ − 2n + 1))` | `x³ − 2x − y² = −1` — 타원곡선 | 3 | 15 |
| `(n, 2ⁿ)` | 찾지 못했습니다 — 없는 규칙을 지어내지 않습니다 | — | 60 |

찾은 관계에는 이름도 붙입니다 — 직선, 원, 타원, 쌍곡선, 포물선, 3차 함수의
그래프, 타원곡선(판별식이 0 이 아닌 3차곡선), 특이점을 가진 3차곡선, n차 대수곡선.

표와 그림에는 앞의 열네 항만 쓰지만, 관계를 찾을 때에는 예순 항까지 꺼내 씁니다.
높은 차수를 말하려면 점이 그만큼 있어야 하기 때문입니다.

### 3-5. 함수·곡선에서 찾는 것

정의역 / 우함수·기함수 / 주기 / 영점 / 극값 / 변곡점 / 수직·수평·사선 점근선 /
도함수 / 부정적분, 그리고 음함수라면 이차곡선의 종류(판별식과 3×3 행렬식을
**정확한 값으로** 계산)와 중심, 대칭, 매개변수를 없앤 식(종결식).

값을 잔뜩 찍어 보고 "여기가 가장 큰 것 같다" 고 말하는 대신, 될 수 있으면
**풀어서** 답합니다. `f′(x) = 0` 을 정확히 풀면 극값의 위치가 `√3/3` 처럼
정확한 식으로 나옵니다.

무한히 많은 영점은 늘어놓지 않고 집합으로 적습니다 — `sin x = 0` 의 해는
`{n·π : n ∈ ℤ}` 입니다.

### 빠르기

정확함을 포기하지 않고 빠르게 하는 길은 **묻는 순서**에 있습니다. "이 둘이
같은가" 를 물을 때 먼저 고정밀 수치로 재어 보고, 뚜렷이 다르면 거기서 끝냅니다.
0 에 아주 가까울 때만 기호로 증명합니다. 증명할 때도 싼 길부터 밟습니다 —
cos·sin 을 지수꼴로 바꿔 펴기만 해도 삼각함수 항등식은 저절로 풀리는데,
`sympy.simplify` 보다 쉰 배 빠르면서 어림이 아니라 증명입니다.

식을 다듬는 일도 마지막으로 미룹니다. 회전행렬 후보를 예쁘게 만든 뒤에 확인하면
버려질 후보를 다듬느라 시간을 쓰게 되므로, **한 점으로 먼저 걸러 내고** 살아남은
것만 다듬습니다.

| 분석 대상 | 전 | 후 |
| --- | --- | --- |
| `P(n) = (n, n²)` | 0.9초 | 0.13초 |
| `P(n) = (n, sin n)` | 8.1초 | 0.45초 |
| `P(n) = (cos n, sin n)` | 6.7초 | 2.5초 |
| `aₙ = sin n` | 0.68초 | 0.12초 |

결론은 하나도 달라지지 않았습니다 — 시험이 그것을 지킵니다.

### 왜 직접 만들었나

SymPy·mpmath·NumPy·SciPy·PySide6 는 각자 잘하는 일이 있습니다. 하지만
라이브러리가 대신해 주지 않는 것들이 있어 직접 만들었습니다.

- **점열 처리** — 화면에 들어오는 번호만 정확한 좌표로 (`objects/pointseq.py`)
- **해집합 표현** — 이산인가 연속인가를 그림보다 먼저 정한다 (`core/solution.py`)
- **적응형 그래프** — ε 을 기준으로 필요한 곳만 세분 (`engine/`)
- **규칙성 탐색** — 차분·점화식·불변량 (`analysis/`)
- **가설 검증** — 세우는 데 쓰지 않은 항으로 확인 (`analysis/finding.py`)
